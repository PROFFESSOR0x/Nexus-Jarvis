# نكسس — نظام الوكلاء المتعددين (NEXUS)

نكسس نظام وكلاء **قائد + عمّال** بواجهتين: طرفية نصية (TUI) ولوحة ويب حيّة على طراز جارفس.

**وكيل قائد** واحد يملك كل محادثة: يجيب مباشرة عن البسيط، يستخدم الأدوات بنفسه للمهمة المفردة، وعندما تنقسم المهمة لأجزاء مستقلة **يعيّن عمّالاً** يعملون بالتوازي، يتخاطبون عبر راديو مشترك وينسّقون على خطة جماعية، ثم يتحقق القائد ويجمع النتائج في **إجابة نهائية واحدة** لكل دور.

- 🖥️ **واجهة طرفية (TUI)** — محادثة، سجل أدوات، جلسات، إحصاءات، ذيل لحظي للسجلات
- 🛰️ **لوحة الويب** — موارد النظام لحظياً، مخطط الوكلاء، راديو العمّال، النشاط، التفكير الحي، طرفية، سجلات، ذاكرة
- 🧠 **ذاكرة طويلة المدى** — ملفك الشخصي وحقائقك في `~/.nexus/memory.json`، تبقى بعد إعادة التشغيل
- 🛠️ **أدوات حقيقية** — صدفة النظام (shell)، تنفيذ الأكواد (python / javascript / c / cpp / csharp / pwsh)، بحث الويب، جلب الصفحات، تنفيذ متوازٍ
- 📻 **عمل جماعي** — جولات تفويض براديو وخطة مشتركة وميزانية خطوات لكل عامل
- 📝 **كل شيء مسجّل** — كل استدعاء أداة ونموذج وحفظ ونتيجة في `nexus.log`
- 💬 **أوامر slash** — الجلسات، النماذج، جهد التفكير، الذاكرة (`/help` للكل)

> English docs: [README.md](README.md)

> ⚠️ **تحذير بحثي — اقرأ أولاً:** وكلاء نكسس يعملون **بلا أي قيود**: ينفذون أوامر صدفة حقيقية وأكواداً برمجية ويتصفحون الويب **بلا عزل وبلا بوابات موافقة وبلا حواجز حماية**. هذا المشروع **بحثي بحت**. شغّله فقط على جهاز أو جهاز افتراضي تتحمّل كسره، وليس أبداً على أنظمة إنتاجية أو بجانب بيانات حساسة. **أنت وحدك المسؤول عن كل ما يفعله الوكلاء.**

## 2. التثبيت

### الخطوة 1 — ادخل مجلد المشروع

```bash
cd nexus
```

### الخطوة 2 — بيئة افتراضية وتثبيت الاعتماديات

ويندوز (PowerShell):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

لينكس / ماك:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

هذا يثبّت: `textual rich httpx python-dotenv ddgs html2text openai ollama fastapi "uvicorn[standard]" psutil`.

### الخطوة 3 — ثبّت Ollama (إن كنت ستستخدمه) واسحب نموذجاً

1. ثبّت من [ollama.com](https://ollama.com) وتأكد أنه يعمل على `http://localhost:11434` (جرّب `ollama list`).
2. اسحب نموذجاً واحداً على الأقل، مثلاً:

```bash
ollama pull qwen:14b
```

النماذج السحابية (مثل `gpt-oss:120b-cloud`) تعمل أيضاً بعد تسجيل الدخول في Ollama.

*تستخدم OpenAI بدلاً منه؟ تخطَّ Ollama وضع `LLM_PROVIDER=openai` مع `OPENAI_API_KEY` في `.env`.*

### الخطوة 4 — اضبط ملف `.env`

انسخ `.env` المرفق وعدّل القيم (كل المفاتيح مشروحة أدناه). أبسط مثال يعمل مع Ollama:

```ini
LLM_PROVIDER=ollama
OLLAMA_MODEL=qwen:14b
OLLAMA_HOST=http://localhost:11434
```

## 3. الإعدادات (مرجع `.env`)

| المفتاح | الافتراضي | وظيفته |
| ------ | --------- | ------ |
| `LLM_PROVIDER` | `openai` | ‏`ollama` أو `openai` |
| `LLM_MODEL` | `gpt-4o` | اسم النموذج مع OpenAI |
| `OPENAI_API_KEY` | — | مفتاح API (وضع openai) |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | أي نقطة متوافقة مع OpenAI |
| `OLLAMA_MODEL` | `llama3.1` | اسم النموذج مع Ollama |
| `OLLAMA_HOST` | `http://localhost:11434` | عنوان خادم Ollama |
| `LLM_TEMPERATURE` | `0.7` | حرارة التوليد |
| `LLM_MAX_TOKENS` | `8192` | أقصى طول للرد |
| `THINK_EFFORT` | `medium` | عمق التفكير: `low` / `medium` / `high` (أصيل في Ollama) |
| `MAX_ITERATIONS` | `100` | خطوات القائد في الدور الواحد |
| `MAX_SUBAGENTS` | `100` | أقصى عدد عمّال في الجولة |
| `SUBAGENT_MAX_ITERATIONS` | `100` | خطوات كل عامل |
| `DELEGATE_MAX_ROUNDS` | `100` | جولات التفويض في الدور |
| `WORKSPACE_ROOT` | `~/.nexus/sessions` | مكان الجلسات |
| `WEB_HOST` / `WEB_PORT` | `127.0.0.1` / `8777` | عنوان لوحة الويب |

> ملاحظة: `/model` و `/thinking` يبدّلان النموذج والجهد **مباشرة** ويحفظان في `.env` — بلا إعادة تشغيل.

## 4. التشغيل

| الوضع | الأمر | ملاحظات |
| ----- | ----- | ------- |
| الطرفية | `python main.py` | `Ctrl+N` جلسة جديدة، `Ctrl+S` حفظ، `Ctrl+L` مسح، `Ctrl+Q` خروج |
| الويب | `python main.py --web` | افتح http://127.0.0.1:8777 · `--host` / `--port` للتغيير، `--session <id>` للاستئناف |
| سطر الأوامر | `python main.py --cli` | وضع منفرد صامت، أضف `--prompt "..."` لتخطي سطر الإدخال |

اللوحة ترفض الإقلاع إذا كان المنفذ مشغولاً (حماية من تشغيل نسختين) — أوقف القديمة بدل التكديس.

## 5. الاستخدام

**تحدث طبيعياً.** التحيات والأسئلة المعرفية تُجاب مباشرة، وما يحتاج أدوات يُنفَّذ، والمهام المركبة تُفوَّض للعمّال ثم تُجمَّع.

**أوامر slash** (قائمة إكمال تلقائي في طرفية الويب بزر `/`، وبطاقات كهرمانية في الطرفية النصية):

| الأمر | الأثر |
| ----- | ----- |
| `/new` | جلسة جديدة |
| `/sessions` | المحادثات القديمة (مع لمحات) |
| `/open <id…>` | العودة لمحادثة قديمة (يُسترجع سياقها) |
| `/delete <id…>` | حذف محادثة (ليست النشطة أبداً) |
| `/models` | النماذج المتاحة (مباشرة من Ollama) |
| `/model <name>` | تبديل النموذج فوراً + حفظ |
| `/thinking [low\|medium\|high]` | عرض/ضبط جهد التفكير |
| `/memory` | ماذا يتذكر نكسس عنك |
| `/clear` | مسح الشاشة (محلي) |
| `/help` | هذه القائمة |

**الذاكرة:** يسألك نكسس عن اسمك وعملك عندما تكون ذاكرته فارغة ثم يحفظها دائماً. اسأل *"ماذا تتذكر عني؟"* في أي وقت، وقل *"انسَ X"* للمسح.

**التفويض باختصار:** القائد ملزَم بالتوزيع عند وجود مسارين مستقلين أو أكثر (استدعاء `agent.delegate` واحد) وفق إطار ROLE/GOAL/CONTEXT/METHOD/OUTPUT/TALK. العمّال يتخاطبون بالراديو (`agent.say`) وينسّقون بالخطة (`agent.plan`) ولا يفوّضون بدورهم، وإنجازاتهم تُسجَّل `[SUBAGENT]` — وإجابة `[AGENT]` نهائية واحدة فقط في الدور.

## 6. لوحات الويب

| اللوحة | تعرض |
| ------ | ---- |
| SYSTEM / NETWORK | المعالج والذاكرة والقرص لحظياً، أعمدة الأنوية، أهم العمليات، مخطط الشبكة |
| ENTITY | مخطط الوكلاء: القائد + الكيانات، شريحتا النموذج والذاكرة، نبضات الإشارات، نقاط الأدوات لكل وكيل؛ **البطاقات قابلة للسحب** (ونقرة مزدوجة للreset) |
| TOOL I/O | سجل ثابت لكل استدعاء أداة بعرض أصيل (نوافذ طرفية، جداول، JSON ملوّن) |
| AGENTS | القائد والجولات وبطاقات العمّال بالتوقيتات وعدّادات الراديو |
| MEMORY | الملف الشخصي وأحدث الحقائق (تحديث تلقائي) |
| COMMS | حركة الراديو وعمليات الخطة |
| ACTIVITY | سجل الأدوات بالحالة والتوقيت |
| THINKING | التفكير الحي (القائد + العمّال) |
| TERMINAL | المحادثة (ماركداون + جداول + رياضيات LaTeX + عربي RTL) |
| LOGS | ذيل `nexus.log` لحظياً |

## 7. بنية المشروع

```text
nexus/
├── main.py            # كل الخلفية: الأدوات، الوكلاء، الطرفية، الجلسات، الذاكرة، السجلات
├── webui.py           # خلفية الويب: REST + WebSocket + إحصاءات النظام
├── web/               # الواجهة: index.html و app.js و styles.css (بلا بناء وبلا CDN)
│   ├── index.html
│   ├── app.js
│   └── styles.css
├── system_prompt.txt  # تعليمات القائد (الإلزام، إطار المهام، الدروس)
├── nexus.log          # كل أداة/نموذج/حفظ/نتيجة (تدوير 2MB × 3، مستثنى من git)
├── requirements.txt
├── .env               # إعداداتك (مستثنى من git — لا ترفعه أبداً!)
├── .env.example       # قالب بقيم افتراضية آمنة (ارفع هذا بدلاً منه)
├── .gitignore
├── LICENSE            # رخصة MIT
├── README.md          # الإنجليزية
└── README.ar.md       # هذا الملف (العربية)
```

بيانات التشغيل خارج المستودع: الجلسات في `~/.nexus/sessions/{id}/` (‏`session.json` و `context.json` ومجلد `workspace`)، والذاكرة في `~/.nexus/memory.json`.

## 8. استكشاف الأخطاء

| العرض | السبب / الحل |
| ----- | ------------ |
| اللوحة لا تقلع: المنفذ مشغول | خلفية أخرى تملكه — أوقفها ولا تكدّس الخوادم |
| الترويسة: LLM OFFLINE | Ollama لا يعمل (`ollama serve`) أو `OLLAMA_HOST` خطأ |
| `[Ollama error] … 500` | عثرة سحابية من Ollama — نكسس يعيد المحاولة مرتين تلقائياً ثم يعتذر بأدب؛ أعد الإرسال أو بدّل لنموذج محلي بـ `/model` |
| `session.json` تالف/فارغ | الحفظ ذرّي والقارئ متسامح — أسوأ الحالات: `/new` |
| عمّال صامتون / ميزانية منتهية | التعليمات تلزم الانضباط الراديوي و100 خطوة؛ راقب COMMS |
| الواجهة تبدو قديمة | تحديث قسري (Ctrl+F5)؛ الأصول موسومة بإصدار (`?v=`) |
